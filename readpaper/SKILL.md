# ReadPaper

以读者能独立复述机制、批判局限、提出下一步并回答验收题为目标。默认中文，一次讲透当前问题，不逐节翻译全文。ReadPaper 包含完整 DrawPaper 工作流；只安装 ReadPaper 也能进入绘图流程，DrawPaper 同时保留独立入口。

## 进入任务

1. 读取当前工作区 `AGENTS.md`、总台账和该论文主文档。已有项目沿用其规则、目录和读者背景，不把其他学科硬套成机器人研究。
2. 定位用户指定的 PDF、版本和 slug。优先本地全文，不能只靠摘要生成精读地图或架构图。缺原文时只完成可独立执行的初始化并说明缺项；版本或目标目录确实无法判断时才问一个必要问题。
3. 新建精读项目或加入一篇论文时，读 [工作区与初始化](references/workspace.md)，运行 `scripts/init_workspace.py` 自动补齐目录、三类 README 和 `AGENTS.md`。脚本相对路径以本技能目录为基准，执行时解析成绝对路径。普通概念问答不因命中技能而创建新项目。
4. 按下表只读本次模式所需说明；保持一篇论文只有一份主文档 `analyse/<slug>/README.md`。

| 用户意图 | 执行 |
|---|---|
| `带我读 <slug>`、开始精读一篇论文 | [四种模式](references/reading-modes.md) 的 A；完成地图和默认绘图后停止讲解 |
| 随读提问、贴原文/公式/图 | 模式 B；只补符号、直觉、推导、动机中当前卡住的一层 |
| `验收 <slug>`，提交八题答案 | 模式 C；核对原文、判题、记错题，依据结果更新状态 |
| `落盘` | 模式 D；直接写文件并更新索引，最终只回一行路径与摘要 |
| 只画或修改论文图 | 调用 DrawPaper；不额外生成整套阅读地图和验收题 |
| 仅初始化 | 补齐框架后停下；不能把空框架标记为已读或已绘图 |

## 教学与证据

- 默认每次回复不超过 500 字，涉及公式可放宽到 800 字，一次不超过三个概念；六块开卷地图和八题判词为完整性可适度超出，不顺带展开课程。
- 先用具体场景解释“在干什么、为什么需要”，再讲数学。先定义符号、含义和形状/维度，再给公式。
- 聊天及 Markdown 笔记中，所有数学符号、变量、上下标、维度和公式均独立使用 `$$...$$`，不使用行内数学。三列符号表无法正常渲染时改成逐项列出“符号、含义、形状/维度”，符号与维度仍各自独立成行。TeX 图源使用正常 LaTeX 数学环境，保证渲染结果准确。
- 章节号、公式号、图号、数值、baseline、维度和实现细节必须有原文依据；没定位到就直说，不编造近似出处。区分论文事实、教学类比和研究设想。
- 给出最适合当前目标的解释或行动，不列选择菜单。结尾最多一个追问入口；用户说“懂了”就停止。
- 自发跨论文类比仅使用总台账中“已验收”的论文；用户明确要求比较未验收论文时按要求核对来源，不假装用户已经读懂。

## 内置 DrawPaper

开卷默认把图作为“核心机制”的一部分完成，无需用户再发一次绘图请求。用户明确说暂不画图、只答问题或只初始化时遵循当前要求。已有同版本、同范围且完成核验的图可直接复用，缺失或过期部分才重做。

读 [绘图衔接](references/drawpaper-integration.md)，优先读取当前可用的独立 `$drawpaper` 技能；若没有安装，读取随包内置的 [DrawPaper 工作流](bundled/drawpaper/WORKFLOW.md)。以实际读取文件的目录解析图片、脚本和相对引用。不要要求用户再次安装同一个工作流。

从论文核对输入、内部计算、输出、损失与训练/部署链路，交付关键原图、选定生图草稿、PDF、完整 PNG 和可重编译源码。完成编译、最新预览的整图及局部检查后，才记为图已核验；“已核验图”不等于“论文已验收”。工具缺失时保留能完成的部分并明确未完成项，不以占位图或只有草稿冒充终稿。
