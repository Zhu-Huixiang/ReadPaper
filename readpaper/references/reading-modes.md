# 四种阅读模式

## A：开卷

读全文，复查方法、关键公式、算法、架构图和相关附录。使用当前 PDF 技能/工具并记录版本，无法读取的页或公式标为未核验。已有地图续读时不重置用户答案和错题。

输出且只输出六块，写入 `notes/map.md`，原样存档到主 README 第 2 节：

1. **一句话贡献**：到底做成了什么事。
2. **它在跟谁吵架**：前人做法与痛点，约五句，不把未核实的批评写成作者结论。
3. **核心机制**：每条不超过五句，核对并标注 § / Eq / Fig，从场景到计算机制。默认把 DrawPaper 完整预览和交付入口嵌入本块，不另加第七块。
4. **两个魔鬼细节**：从实现或附录挑出真正影响理解/复现的两点；缺证据就说明，不能凑数。
5. **与我主线的关系**：一句话说明与当前读者方向的联系及是否值得深读，不硬扯。
6. **验收问题 8 条**：L1 概念三题、L2 机制三题、L3 批判两题。答案可判定；至少两题解释公式物理含义或手推一步，至少一题问去掉模块的后果。题干不泄露答案，不在地图或图中附答案键。正常机制讲解可以提供答题所需知识；用户后续直接问到某题时可以解释。

论文无可定位公式时说明限制，使用论文明确的计算关系做两道一步推演题，不冒充原文公式，不为套题型发明目标函数。

生成地图、图和索引后停止讲课，等用户读后提问。默认绘图在本次开卷内完成；工具障碍导致图未完成时，保留地图，在核心机制块及索引如实记状态，不把部分交付标为全流程完成。

## B：随读答疑

只回答本次问题。判断用户卡在符号、直觉、推导或动机哪层，只补这一层。先场景、符号定义、再数学；一次不超过三个概念，必要时用局部图说明。

“再具体点”就下沉，“懂了”就停。一般问答不重画整张图，也不拆出一堆新文件。用户要求落盘、改文档或确需保存图时才更新产物。

## C：验收

读取原来的八题和论文来源，逐条给出：

`① ✅/⚠️/❌ ｜ 一句判词 ｜ 正确答案关键点（不超过两句）｜ 论文定位（§/Eq）`

用户原答案与判词写入主 README 第 3 节。所有 ⚠️/❌ 及正确理解进入第 4 节错题本；复验保留历史并注明是否纠正。

八题全部正确才判“过”；⚠️ 表示仍有缺口，修正后再判。缺题时仅评价已交部分并指出缺题，状态不升级。最终一行“过 / 不过”，未通过给有来源的重读位置。通过后把总台账改为“已验收”；画完图或完成实验不能替代阅读验收。

## D：落盘

直接把对话整理到当前论文的一份 `notes/<主题>.md`；已有同主题文档优先更新，不把一次解释拆成多份。区分论文事实、用户问题与研究设想，保留来源和未解决点。跨论文内容归 `ideas/`，在相关论文索引关联。

更新主 README 文件索引。最终只回一行“可点击绝对路径 + 一句话摘要”，不复述正文、不附追问。当前论文无法从上下文判断时，只问最必要的归属问题。
